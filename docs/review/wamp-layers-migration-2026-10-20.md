# Layers migration for the remaining wallet-compatibility work

Status: migration plan, linked to F238. No replacement wallet stack is introduced by F239. Jonathan's `crypto-websites-layers` skill requires 1001 Digital Layers for the integration and, for an existing site, inspecting its framework and planning the smallest practical migration. WAMP currently uses Vite/TypeScript/Phaser, AppKit/Wagmi and viem; it is not a Nuxt/Vue application. Its existing authenticated wallet challenge/verify endpoints are distinct from connecting a wallet or sending a room transaction.

Before implementing this migration, read and verify the current upstream getting-started, EVM and component documentation at [1001 Digital Layers](https://github.com/1001-digital/layers/tree/master/docs). Package APIs and supported hosting arrangements have not been assumed or verified here. Compare a supported Layers wallet panel with a Nuxt host for the existing game canvas, then choose the smallest supported integration that preserves the game's loading behavior and visual design. Do not add an improvised alternative connector stack.

Keep Layers behind a typed application adapter: explicit chain, captured linked account/signer/context, cancellation and a submitted-hash callback before receipt waiting. Keep room authorization, transaction preparation, artwork rendering, durable recovery and canonical chain reconciliation in WAMP's existing domain modules. Connecting must not authenticate or authorize spending. Preserve the installed-wallet gate, email-only accounts, classroom restrictions, group rights and original builder credit. Audit and update the existing server challenge/verification protocol for smart accounts with F238; do not assume Layers' SIWE is automatically compatible with the current protocol.

Re-run dismissal, unavailable-connector, signer/account change, two-stage collection, late-hash, reload, responsive, no-wallet and zero-idle-work checks at the real integration boundary. Add no signing key or paid provider credential to the browser. Do not send a real signature or transaction to test this work. F239's recovered pending transactions and saved drafts must remain readable across migration.
