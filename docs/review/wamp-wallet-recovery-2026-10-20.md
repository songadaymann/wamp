## Required outcome

A collected room or completed artwork update must recover after a wallet hop, backgrounded tab, reload or receipt timeout. Retain the returned transaction hash durably before waiting for its receipt. Reconcile from verified chain ownership and canonical artwork using the existing authenticated fresh endpoint, rather than asking for another approval to repair the game's cache. Offer Close and Check again during wallet waits. Cancelling UI must stop stale continuation while a late returned hash can still be retained for its captured room/account. An unknown outcome must not cause another send or a repeat mint. Preserve dirty drafts, permissions, builder credit and all school/World/Expanded Room restrictions.

Before F239, the sender called onSubmitted before receipt waiting but mint did not use it. Artwork remembered the hash only in the room session and could discard it after a generation change or reload. The generic busy overlay hid Close/Retry while waiting. F237 sequencing and F242 canonical metadata truth are delivered prerequisites, not proof that F239 is already done. Read both F239 fact-check sections in wamp-checkup-2026-10-details.md5479+ before implementation. The global event-index cron is explicitly optional at the audited scale and is not required for this finite recovery path.

## Implementation checkpoint (not a release)

- Extracted collection/artwork into `src/scenes/editor/roomWalletActions.ts`; RoomSession is smaller. Both actions record a captured intent immediately before the actual send and durably retain a returned hash before receipt waiting, including late hashes after Close/reset. A definite pre-hash rejection or verified revert clears only its matching record. Unknown results remain pending and block another send. Storage is validated, bounded to16 entries and32KB, refuses eviction of unknown approvals, and reports an in-memory fallback when writes fail.
- Finite recovery uses the existing authenticated fresh ownership/artwork endpoint; receipt checks use only the fixed public Base/Base Sepolia endpoints, verify the network/hash/recipient/sender, and cannot send. The shared coordinator deduplicates overlapping checks, keeps current canonical artwork when an older update was superseded, and leaves unknown results pending. Load/return checks make at most3 attempts with a45-second overall deadline and no recurring timer. Nothing pending creates no recovery request or timer and loads no wallet SDK.
- Wallet waits have Close/Check again. Cancellation releases room/collection locks, suppresses automatic stage two and stale UI, while an underlying provider can still deliver a captured hash. Room/world/scene/account and connected-signer changes are fenced, including away-and-back changes; the expected signer may connect initially. A successful automatic check also finishes an otherwise-hung foreground wait without starting another approval. Fresh rights/artwork do not replace dirty tiles, titles or draft timestamps. Observers are removed/restarted across editor shutdown/re-entry.

History/account/editor status have non-crypto text; a browser without a wallet uses ordinary edit permissions without a dedicated chain refresh. Saved recovery is dormant while the wallet gate is off. The existing wallet browser suites now explicitly select the documented wallet-enabled test state.
