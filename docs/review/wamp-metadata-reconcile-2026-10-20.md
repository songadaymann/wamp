## Implementation and read-only cache plan

Fresh ownership refresh now includes the token URI with coordinates, owner and token at one pinned block, within the existing12-second abort and5-second call deadlines. The extra block/URI reads occur only for explicit fresh refresh; ordinary tolerant saves keep their existing call count and idle operation adds no requests. Metadata transaction verification/persistence moved out of the ownership service into mint/metadata.ts. Confirmation derives the canonical legacy/compact version and checks configured identity; a conditional metadata-only UPDATE RETURNING prevents overwriting concurrent token/cache changes. Empty, unsupported, foreign and invalid-version payloads clear a stale version claim while recording only a verified URI hash. No external metadata URL is fetched. Provider failure preserves the cache and fails the explicit refresh without presenting stale data as fresh.

The new `npm run mint:metadata:reconcile -- ...` command defaults to read-only. It reads narrowly scoped D1 cache fields and public chain state; it never loads a wallet key or sends a transaction. Applying requires the exact saved plan digest, a fresh chain/identity/cache match, a conditional update and post-write verification. It checkpoints pending/acknowledged rows so a partial/uncertain outcome is not mislabeled complete. Output is restricted to ignored output/. The CLI uses a locked dev dependency for its TypeScript runtime so CI and strangers can run it without an implicit download.
